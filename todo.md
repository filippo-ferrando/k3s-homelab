## Phase 1: Infrastructure & K3s Cluster Provisioning (Ansible)

Execute the Ansible playbooks sequentially from your management laptop.

1. **Prepare Node Operating Systems** (Installs NFS/iSCSI utilities and configures firewall rules):

```bash
ansible-playbook -i ansible/inventory.ini ansible/01_os_prep.yml
```

1. **Bootstrap K3s Cluster & Deploy Argo CD Core**:

```bash
ansible-playbook -i ansible/inventory.ini ansible/02_bootstrap_cluster.yml
```

1. **Configure & Mount NFS Shares Across Nodes**:

```bash
ansible-playbook -i ansible/inventory.ini ansible/04_deploy_nfs_shares.yml
```

1. **Deploy Host Backup Scripts on `magi**`:

```bash
ansible-playbook -i ansible/inventory.ini ansible/03_deploy_borg_backups.yml
```

1. **Fetch Kubeconfig to Management Laptop**:

```bash
mkdir -p ~/.kube
scp magi@192.168.10.100:/etc/rancher/k3s/k3s.yaml ~/.kube/config
# Update server address in local kubeconfig
sed -i 's/127.0.0.1/192.168.10.100/g' ~/.kube/config
kubectl get nodes
```

## Phase 2: GitOps Bootstrap (Argo CD Kickoff)

Initiate the GitOps engine by applying the root application manifests.

1. **Apply Root Applications**:

```bash
kubectl apply -f system/root-app.yaml
```

1. **Retrieve Initial Argo CD Admin Credentials**:

```bash
kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d; echo
```

* **URL:** `[https://argocd.internal.fferrando.cc](https://argocd.internal.fferrando.cc)`[cite: 20]
* **Username:** `admin`

1. **Observe Initial Sync State**:

* Argo CD will deploy `sealed-secrets` first due to sync-wave `-2`.

* Components like `cloudflared` and `cert-manager` will briefly report errors or missing secrets. **This is expected during Two-Phase Boot.**

## Phase 3: Secret Generation & Sealing

Fetch the public encryption key generated by the newly installed Sealed Secrets controller and create all required cluster secrets.

1. **Fetch Cluster Public Key**:

```bash
kubeseal --fetch-cert \
  --controller-namespace kube-system \
  --controller-name sealed-secrets > kubeseal-cert.pem

```

1. **Generate Cloudflare API Token Secret (`cert-manager`)**:

```bash
kubectl create secret generic cloudflare-api-token-secret \
  --namespace cert-manager \
  --from-literal=api-token="YOUR_CLOUDFLARE_API_TOKEN" \
  --dry-run=client -o yaml | \
kubeseal --cert kubeseal-cert.pem --format yaml > infrastructure/cert-manager/sealed-secret.yaml

```

1. **Generate Cloudflare Tunnel Token Secret (`cloudflared`)**:

```bash
kubectl create secret generic tunnel-token \
  --namespace cloudflared \
  --from-literal=token="YOUR_CLOUDFLARE_TUNNEL_TOKEN" \
  --dry-run=client -o yaml | \
kubeseal --cert kubeseal-cert.pem --format yaml > infrastructure/cloudflared/sealed-secret.yaml

```

1. **Generate Longhorn UI BasicAuth Secret (`longhorn-system`)**:

```bash
# Generate htpasswd string (replace with your desired password)
HTPASSWD_HASH=$(htpasswd -nb admin "YourStrongPasswordHere")

kubectl create secret generic longhorn-auth-secret \
  --namespace longhorn-system \
  --from-literal=users="${HTPASSWD_HASH}" \
  --dry-run=client -o yaml | \
kubeseal --cert kubeseal-cert.pem --format yaml > infrastructure/longhorn/sealed-secret.yaml

```

1. **Clean Up Local Cert**:

```bash
rm kubeseal-cert.pem

```

## Phase 4: Commit Secrets & GitOps Convergence

1. **Commit and Push Sealed Secrets to GitHub**:

```bash
git add infrastructure/cert-manager/sealed-secret.yaml \
        infrastructure/cloudflared/sealed-secret.yaml \
        infrastructure/longhorn/sealed-secret.yaml
git commit -m "feat(security): add sealed secrets for cert-manager, cloudflared, and longhorn"
git push origin main

```

1. **Verify Self-Healing Sync in Argo CD**:

* Watch Argo CD automatically pull the new manifests.
* Verify `sealed-secrets` decrypts the resources into standard `Secret` objects.
* Confirm that `cert-manager`, `cloudflared`, and `longhorn-ui` automatically move to a `Healthy` / `Synced` state.
